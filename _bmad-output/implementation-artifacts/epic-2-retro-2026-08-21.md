## Findings

Phase 2 ran the three code lenses of `bmad-review` (adversarial, edge-case-hunter, verification-gap) **inline over the epic diff** — sub-agent delegation is unreliable on this deployment (provider 5xx/false-done history), so the lenses ran sequentially in one session; the narrowing is recorded per the missing-evidence rule. Aggregate views were derived from the git_evidence pre-pass plus direct reads of every file the epic added.

### Aggregate views

**AV-1 — Architecture delta (checked, clean).** Three new Lambdas (`transcode`, `event-publisher`, `sfn-trigger-shim`), one state machine, one SQS queue, one EventBridge rule, one ESM. All dependency edges flow through the shared layer (`shared.clients` gained exactly one factory, `states_client()`, +4 lines at `lambdas/_shared/clients.py:99-102`). No cycles, no layering violations: shim → SFN only, publisher → EventBridge only, transcode → S3 only; each IAM role matches its code's actual surface (`terraform/processing.tf:82-108,144-171`, `terraform/trigger.tf:124-159`). The ASL is the only cross-story contract and it is mirrored by a committed test (see wins).

**AV-2 — Duplication map (finding F1).** `_require_field` exists verbatim twice — `lambdas/transcode/handler.py:67-76` and `lambdas/event_publisher/handler.py:80-89` — two sessions independently writing the same 10-line validator (the upload handler has its own third validation style). Related: the shim's `_is_execution_already_exists` (`lambdas/sfn_trigger_shim/handler.py:85-89`) duck-types ClientError by class name exactly like `shared.errors.is_conditional_check_failed` — already in deferred-work.md (Story 2.3 entry). And the hand-maintained zip `source{}` blocks grew from 2 copies to 3 (`terraform/upload.tf`, `terraform/processing.tf:38-65`, `terraform/trigger.tf:80-107`): adding a module to `lambdas/_shared/` now requires three synchronized edits, with failure surfacing only as an ImportError at live invoke.

**AV-3 — Size growth (checked, clean).** Top churn is test files (test_sfn_trigger_shim.py +476, test_transcode.py +398, test_event_publisher.py +369). Handlers are 129/131/192 lines. No god-class candidate.

**AV-4 — Pattern divergence (finding F2).** The transcode and publisher validators STRIP whitespace-padded fields before use; the shim validates with `.strip()` but passes the RAW values into the ASL input (`lambdas/sfn_trigger_shim/handler.py:139-148` builds `asl_input` from `detail[name]`, not `detail[name].strip()`). A whitespace-padded `videoId` would pass the shim's check, start an execution, then fail at MarkProcessing's DynamoDB Key match with the record already acked — the exact "fails mid-flight after ack" failure the spec change log says the widened field check was meant to prevent.

**AV-5 — Spec-to-implementation reconciliation.**
- ASL built exactly as specified: four-state chain, condition pairs mirroring `LEGAL_TRANSITIONS`, `processedKey` + `updatedAt` writes, publisher fed domain payload only with `bucket` from env (`terraform/processing.asl.json`, spec-2-2 Design Notes). ✓
- **Accepted deviation, recorded:** floci's `lambda:invoke` returns the result directly (no `{Payload}` wrapper) — probe-verified 2026-08-20, documented in the ASL Comment (`terraform/processing.asl.json:2`), spec-2-2 Design Notes, and mirrored in test. On real AWS a `ResultSelector` would be required.
- `sizeBytes` travels through the ASL but is intentionally absent from the `video.processed` detail shape (`lambdas/_shared/events.py:79-88`) — the AD-6 shape is fixed; not a defect.
- **Stale doc (finding F3):** README still presents Story 2.3 as future work — "The dashed edge is **planned** (Story 2.3…)" (`README.md:56-57`) and "⏭️ **Next:** Story 2.3" (`README.md:288-289`) — after 2.3 merged. This is the docs item split out of Story 2.3's scope (deferred-work.md), so it is tracked, not silent.

### Diff-scope review lenses

**Adversarial** (findings beyond the aggregate views):
- **F4 — a transient publisher failure loses the terminal event permanently.** MarkProcessed acks before PublishProcessed; if `put_events` fails transiently the execution fails with the record already PROCESSED, and the shim's dedupe (`eb-{eventId}`) blocks any re-drive for that video. FR-8's "exactly one event" degrades to zero on a transient blip. The spec's "no Catch/Retry — any task failure fails the execution" covers FR-11 no-regression but not this. Accepted for the v1 lab (no FAILED path, no retry design yet); the ceiling is named so Epic 3/4 consumers don't assume event presence proves processing.
- **F5 — a transient failure mid-execution strands the record at PROCESSING** (same no-Catch/Retry design; `terraform/processing.asl.json` has no Retry/Catch blocks). Documented as intentional in spec-2-2 ("the FAILED status path stays deferred"); accepted, with the same ceiling.
- **F6 — transcode reads the whole object into memory** (`lambdas/transcode/handler.py:104`); documented "lab objects are small". Accepted with a ceiling.
- Checked and clean: execution-name regex is match-anchored (`handler.py:61,132`); queue visibility timeout 300s = 10× function timeout (`terraform/trigger.tf:25`); rule matches detail-type only by design (any producer of `video.uploaded` triggers — spine routing rule, `terraform/trigger.tf:51-53`); publisher raises on `FailedEntryCount > 0` (`event_publisher/handler.py:121-124`).

**Edge-case hunter** (unhandled paths only):
- F2 (above) is the one unhandled path found: whitespace-padded ASL input fields (shim validates stripped, passes raw).
- Checked and handled: trailing-slash `originalKey` → `MalformedInputError` (`transcode/handler.py:84-86`); missing source object → raw S3 error fails the execution (by design); unparseable/partial SQS records → logged + acked per the documented no-DLQ v1 policy (`sfn_trigger_shim/handler.py:121-146`).

**Verification gap:**
- **F7 — the epic's dominant gap, recurring in all three stories: no automated backstop for deployed wiring.** Unit tests import from the source tree with monkeypatched clients; nothing executes the zips, handler strings, env-var names, or IAM policies the Terraform actually deploys — a dropped zip `source{}` block or renamed env var ships green through all 5 CI stages and fails at first live invoke. Already tracked as three deferred-work.md entries (2.1 transcode scenario, 2.2 state-machine runtime scenario, 2.3 trigger-leg scenario); this retro consolidates them because Epic 3 builds consumers on top of this wiring.
- **F8 — the ASL's runtime data-flow (`$.key`→`originalKey`, `$.processedKey` chaining) is exercised only by manual/live runs.** `test_asl_definition.py` is source-text-only (parses the JSON, asserts structure — a real backstop for the transition table, but it never executes a mapping). Deferred-work.md (2.2) tracks it; this retro's live probe exercised the mappings successfully but is not committed/re-runnable.
- **F9 — `shared.clients` factory service names are untested** (`states_client()` → `"stepfunctions"`; a typo fails first at live invoke). Deferred-work.md (2.3) tracks it.
- Checked and verified: the flat Detail wire shape IS asserted at the publisher (`test_event_publisher.py:147-160`); the ASL↔`LEGAL_TRANSITIONS` mirror IS asserted (`test_asl_definition.py`); shim dedupe/ack semantics are covered by 25 unit tests (`test_sfn_trigger_shim.py`). 173 tests pass (`pytest lambdas/ -q`, 2026-08-21).
