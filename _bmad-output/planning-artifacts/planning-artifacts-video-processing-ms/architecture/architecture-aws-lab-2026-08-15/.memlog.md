- (decision) Design paradigm: layered (controller->service->repository) in every service; the cross-service pipeline is the system-level pattern. Binds all 5 services. Prevents builders choosing different internal structures (hexagonal in one, layered in another). Chosen over hexagonal: services are small, one adapter class each, ceremony buys little.
- (decision) Data ownership / single-writer: video record is owned by metadata-service (sole DB, sole mutator; others write only via its gRPC API, no shared storage). Search index owned by search-service, notification history owned by notification-service — both derived from events and disposable/rebuildable. upload-service and processing-service are stateless workers. videoId generated by ingress (upload-service), not the DB. Prevents two services assuming they own the same data or two codebases writing one entity.
- (decision) Status state machine enforced strictly inside metadata-service (sole mutator): UPLOADED -> PROCESSING -> PROCESSED|FAILED, PROCESSED/FAILED terminal; same-status re-assertion idempotent; regressions and transitions out of terminal rejected with gRPC FAILED_PRECONDITION. Prevents status regression under SQS at-least-once redelivery. Also: all SQS consumers must be idempotent keyed on videoId (upsert, never append-blind) — protects derived stores (search index, notification history) from duplicates.
- (decision) Deployment envelope: now = 5 services as local JVMs on fixed ports + ministack (docker compose) emulating S3/SQS at localhost:4566; gRPC clients use static localhost targets (fixed port table). Config-not-code rule: no AWS endpoint/region/credential or gRPC target built in code; all in application.yml (spring.cloud.aws.*, spring.grpc.client.channel.*.target). Real AWS + kubernetes deferred. One Dockerfile per service pinned now (multi-stage maven->JRE) so containerization/K8s later is mechanical.
- (decision) gRPC contract evolution: versioned from day one. Breaking change = new proto package version (videolab.v1 -> videolab.v2) coexisting with the old until consumers migrate; each service pins the version it compiles against. Implication: java_package must be version-scoped (e.g. com.videolab.proto.v1) because with java_multiple_files=true a single shared java_package collides class names when two versions coexist in one JVM. Story-1 spec currently pins java_package com.videolab.proto — needs renegotiation to version-scope it.
- (decision) Formats & identity conventions: videoId is a UUID generated at ingress (upload-service); all timestamps are epoch-millis int64; queue names video-uploaded/video-processed, buckets video-uploads/video-processed, defined once in video-common Names.java and never string-typed in services; per-service fixed ports: upload 8080, processing 8081, notification 8082, metadata web 8090 + grpc 9090, search web 8091 + grpc 9091.
- (question) processing-service writes metadata via gRPC AND publishes an SQS event: two channels, no atomicity. If one succeeds and the other fails, metadata state and event consumers (search/notify) diverge. Accepted for the lab as eventually-consistent (happy path), with a revisit condition: if divergence is observed or strict consistency required, adopt a transactional outbox in the writer. Tracked under Deferred.
- (decision) Error semantics: gRPC uses standard status codes only (NOT_FOUND, INVALID_ARGUMENT, FAILED_PRECONDITION, ALREADY_EXISTS, INTERNAL); HTTP facades (upload/search) return matching 4xx/5xx with JSON body key error mapping to the message. Prevents each service inventing its own error envelope or status vocabulary. Event payloads are JSON (Jackson) on SQS, named verb-in-past: video.uploaded, video.processed.
- (decision) Identity + contract (reviewer-gate fix, human-approved): videoId minted exactly once at ingress (upload-service) and supplied via CreateVideoRequest optional video_id; metadata honours a present valid UUID, generates if absent, rejects duplicate with ALREADY_EXISTS. VideoInfo gains failure_reason (canonical shape for fields shared with events). Both event DTOs gain eventId (UUID per publish, the idempotency key) and schemaVersion (default 1). Prevents split identity authority and shape drift between gRPC VideoInfo and event payloads.
- (decision) State machine responsibility + ordering (reviewer-gate fix): UPLOADED minted only via CreateVideo; PROCESSING minted only by processing-service at transcode start; PROCESSED|FAILED minted only by processing-service at completion; upload-service NEVER emits PROCESSING. Every terminal transition emits exactly one event on video-processed with status mirroring the acknowledged store status; failureReason populated iff FAILED; notification notifies on PROCESSED and FAILED; search excludes FAILED. Status-first ordering: UpdateVideoStatus completes before the corresponding event is published; terminal event published only after metadata acknowledges the terminal transition.
- (decision) Idempotency + versioning tightened (reviewer-gate fix): idempotency keyed on eventId (every event carries it); videoId is the domain key for merge/upsert semantics; natural keys declared per store (search index: videoId; notification history: eventId). AD-5 extended: proto field numbers and message names immutable within a version (additive-only); renumber/rename/remove is a breaking change -> new version; during coexistence a gRPC server MUST expose both versions (server-side duty); events versioned via schemaVersion, consumers reject unknown versions. Prevents redelivery duplication, field renumbering corruption, and wire-incoherent version coexistence.
- (decision) Error mapping + event trust + env scoping (reviewer-gate fix): explicit gRPC->HTTP table NOT_FOUND=404, INVALID_ARGUMENT=400, ALREADY_EXISTS=409, FAILED_PRECONDITION=409, INTERNAL=500; body {error: gRPC description verbatim}; SSE error/close frames use event: error with the same body. Event trust: events are projections of owner-confirmed state; publishers complete the owning write before publishing; metadata-service is truth for existence/status; a consumer that cannot find videoId in metadata treats the event as poison (drop + log). Publisher allow-list: only upload-service publishes video-uploaded; only processing-service publishes video-processed. AD-6: path-style/region/endpoint are profile-scoped (ministack default, real-AWS profile overrides); gRPC channel names pinned (channel.metadata, channel.search); port table is normative (changing a port is a spine change).
- (decision) Outbox carve-out + reconciliation (reviewer-gate fix): if a transactional outbox is ever adopted it lives in metadata-service's DB and is written through its gRPC API (never a new store inside a stateless worker) - keeps AD-2 single-writer intact. - (decision) AD-9 Single client ingress (API Gateway as edge): binds the API Gateway v2 HTTP API (ministack, Terraform-provisioned), the upload/notification/search HTTP facades, and the client (Bruno). Prevents clients reaching a service directly, service topology leaking to clients, and gRPC becoming a client surface. Rule: all client HTTP traffic (upload, status history, search) reaches a service only through the gateway; gateway routes by path to the correct HTTP facade; responses (status codes, {error} bodies) pass through unchanged (no remapping); gRPC is strictly service-to-service and never gateway-exposed; direct gRPC from the client stays a debugging/inspection surface (FR-21 carve-out); direct client HTTP to a service port is not part of the exercised path (PRD wording kept); no auth on the gateway (lab). The gateway is not a service — it holds no state and is not part of the per-service layered structure.
- (decision) AD-10 Infrastructure as code (Terraform-managed ministack): binds every backing resource the services depend on (video-uploads / video-processed buckets, video-uploaded / video-processed queues, API Gateway v2 API with routes/integrations/stage) and the setup/teardown procedure. Prevents out-of-band resource creation (aws cli or ad-hoc control-plane calls), drift between declared and actual environment, and an irreproducible lab bring-up. Rule: all resources are declared in Terraform and created by terraform apply against ministack; the AWS provider targets http://localhost:4566 (endpoints{} overrides, s3_use_path_style=true, dummy creds, skip credential validation / metadata check); terraform destroy + re-apply rebuilds from the same config; the documented setup/teardown contains no aws cli invocations; local state only (no remote state, modules, or workspaces for the lab). The same .tf targets real AWS in the infra phase (provider config swaps, resource declarations unchanged).
