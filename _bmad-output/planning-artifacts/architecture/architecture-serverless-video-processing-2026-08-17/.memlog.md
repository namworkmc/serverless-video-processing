- (decision) Design paradigm: event-driven serverless pipeline \u2014 API Gateway v2 single ingress -> Lambda handlers -> EventBridge custom bus -> SQS queue per consumer -> consumer Lambdas; Step Functions orchestrates the processing leg via direct service integrations (dynamodb:updateItem, lambda:invoke); DynamoDB is the single source of truth mutated via conditional writes from a shared access layer. No synchronous Lambda-to-Lambda invocation anywhere. Binds all functions, the state machine, the bus, all queues. Prevents builders reintroducing sync RPC between functions (the old Spring Boot gRPC shape) or inventing ad-hoc point-to-point wiring.
- (decision) Event backbone = EventBridge custom bus + SQS queue per consumer (user chose option B over EventBridge-only fanout and SNS fanout). Bus routes video.uploaded -> processing queue; video.processed -> history queue + search queue. Every consumer sits behind its own queue: at-least-once delivery, redelivery, and the PRD's idempotency/poison semantics get an honest home. SNS rejected as over-build for the lab.
- (decision) State machine enforcement = DynamoDB conditional writes via a shared access layer (user chose over a dedicated metadata-Lambda-as-sole-mutator). No metadata service-Lambda exists; every function imports the shared layer (Lambda layer or common package) that owns the legal-transition table and issues UpdateItem with ConditionExpression status = :expected. Illegal transitions are rejected by the table itself (ConditionalCheckFailedException), not a middleman. Same-status re-assertion is idempotent (condition matches, no event). Prevents two functions implementing divergent transition logic and keeps the system purely event-driven (PRD memlog commitment).
- (decision) DynamoDB storage = multiple tables, one entity per table (user chose over single-table design and hybrid): video-metadata (PK videoId), status-history (PK eventId), search-index (PK videoId). Each derived table trivially rebuildable. Title-substring search = Scan with contains filter (DynamoDB has no substring GSI; acceptable at lab scale, NFR-7 performance non-goal). Single-table design deferred as a future learning surface.
- (decision) Step Functions owns orchestration via direct service integrations (user chose over a thin wrapper around one orchestration Lambda). State machine: Task(dynamodb:updateItem UPLOADED->PROCESSING) -> Task(lambda:invoke transcode) -> Task(dynamodb:updateItem ->PROCESSED) -> Task(publish video.processed). Transcode Lambda is a pure worker (S3 in -> S3 out, no status writes, no event publishing). Status-first ordering is structural: the updateItem task completes before the next state. Prevents the state machine becoming decorative and keeps transition/event ordering enforceable in the ASL, not in code.
- (decision) video.uploaded -> Step Functions trigger = queue-based shim (user chose over direct EventBridge->shim): video.uploaded -> processing-trigger queue -> shim Lambda -> StartExecution. Uniform pattern: every consumer sits behind a queue. Shim uses deterministic execution name derived from eventId (eb-{eventId}) so a republish is a dedupe (ExecutionAlreadyExists), never a second execution \u2014 extends NFR-2 to the trigger leg.
- (constraint) floci 1.6.0 EventBridge invoker does NOT support Step Functions state-machine targets (spike-verified: 'unsupported target ARN type' warning, no execution started). The shim Lambda is mandatory on floci, not optional. If floci adds native SFN targets later, the shim can be replaced by a direct target (Terraform-only change, no code change).
- (constraint) floci Lambda service requires the host Docker socket mounted into the floci container (/var/run/docker.sock) \u2014 without it every Lambda invocation fails with 'Failed to start Lambda container: SocketException'. compose.yaml carries the mount (fixed during spike). Binds compose.yaml and any future floci container config.

The Bruno/curl test collection and README must use the _aws/execute-api form; terraform output exposes apiId so the URL is constructible. Host-style execute-api domains fall through to S3.
